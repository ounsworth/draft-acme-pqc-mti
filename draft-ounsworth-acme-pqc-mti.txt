         ACME Post-Quantum Mandatory-To-Implement JWT Algorithm
                  draft-ounsworth-acme-pqc-mti-latest

Abstract

   The ACME protocol specified in RFC8555 requires all implementations
   to support the signature algorithm EDCSA-P256 (ES256) and recommends
   support for Ed25519.  Due to the risk of quantum computers, this
   mandatory-to-implement algorithm is removed, replacing it with ML-
   DSA-65.

1.  Update to RFC8555

   Due to the impending risks of Cryptographically-Relevant Quantum
   Computers (CRQCs), see [RFC9958], [RFC8555] is updated to replace the
   following sentence from Section 6.2:

      An ACME server MUST implement the "ES256" signature algorithm
      [RFC7518] and SHOULD implement the "EdDSA" signature algorithm
      using the "Ed25519" variant (indicated by "crv") [RFC8037].

   is replaced with:

      An ACME server MUST implement the "ML-DSA-65" signature algorithm
      [RFC9964].

2.  Conventions and Definitions

   The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT",
   "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and
   "OPTIONAL" in this document are to be interpreted as described in
   BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all
   capitals, as shown here.

3.  Security Considerations

   This document enhances security by removing the requirement for
   implementations to support soon-to-be-weak algorithms and requiring
   instead mandatory support for the quantum-safe ML-DSA-65 signature
   algorithm.
